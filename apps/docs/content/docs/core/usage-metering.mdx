---
title: Usage Metering
description: Reserve and refund usage before LLM calls
---

Usage metering lets you control whether a request is allowed to run before it reaches the
provider. Use `reserveUsage` to reserve quota or budget before dispatch, and `refundUsage` to
release that reservation when a call fails after reservation succeeded.

`reserveUsage` and `refundUsage` receive `{ coalesced, signal }`.

- `coalesced` is `true` when the caller is sharing an existing in-flight cached request.
- `signal` is the caller-supplied `AbortSignal`, when one was provided.
- A successful reservation is refunded if the request is aborted before the wrapped operation starts.
- If `reserveUsage` fails, no refund is performed because no reservation was created.

```ts title="usage-metering-setup.ts"
const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
});

await llm.call({
  userContent: 'Summarize this document',
  reserveUsage: async ({ signal }) => {
    await billing.reserve({ signal });
  },
  refundUsage: async ({ signal }) => {
    await billing.refund({ signal });
  },
});
```

## How it works

<Cards>
  <Card title="Before the request">
    `reserveUsage` runs before any provider request is dispatched. If it fails, the call stops
    immediately.
  </Card>
  <Card title="After a successful reservation">
    The LLM request proceeds normally. Retries do not trigger `reserveUsage` again because it wraps
    the logical call.
  </Card>
  <Card title="After a failed call">
    `refundUsage` runs when a reservation succeeded but the call ultimately fails.
  </Card>
</Cards>

## Reservation failures

<Callout type="warn">
  If `reserveUsage` throws, the call fails with `LLMError('quota_exceeded')` and no request is sent
  to the provider. The original error is preserved on `err.cause`. A failed reservation is never
  refunded because no usage was reserved.
</Callout>

## With caching

Usage metering also works with `cachedCall` and `cachedLLMCall`.

On a cache miss, the usage flow runs around the underlying call. A cache hit skips the LLM call
entirely, so no new reservation or usage record is created.

```ts title="cached-call-metering.ts"
const result = await llm.cachedCall({
  cacheKey: `cv:${cvId}`,
  ttl: 3600,
  reserveUsage: ({ coalesced, signal }) => quota.reserve(userId, { coalesced, signal }),
  refundUsage: ({ coalesced, signal }) => quota.refund(userId, { coalesced, signal }),
  fn: () => llm.call({ systemPrompt, userContent }),
});
```

## Concurrent cached calls

When multiple callers request the same cache key at the same time, only the first caller runs the
underlying `fn`. Other callers share the same in-flight result.

Each caller still gets its own `reserveUsage` and `refundUsage` lifecycle, its own `signal`, and
its own cancellation behavior. The `coalesced` flag lets your application decide how shared
requests should be metered.

<Callout>
  Although `fn` executes only once per in-flight window, `reserveUsage` and `refundUsage` are still
  invoked once per caller. If `fn` fails, every caller is refunded independently. Aborting one
  coalesced caller does not cancel the shared in-flight `fn` for other callers.
</Callout>

## cachedLLMCall

When using `cachedLLMCall`, provide usage hooks at the cache level. The inner `call()` options are
stripped automatically to prevent reserving usage twice for the same logical request.

```ts title="cached-llm-metering.ts"
const result = await llm.cachedLLMCall({
  cacheKey: `cv:${cvId}`,
  ttl: 3600,
  call: { systemPrompt, userContent },
  reserveUsage: ({ coalesced, signal }) => quota.reserve(userId, { coalesced, signal }),
  refundUsage: ({ coalesced, signal }) => quota.refund(userId, { coalesced, signal }),
});
```

## Relationship with usage tracking

Usage metering controls whether a request can start.

Usage tracking reports provider usage after a provider response through `onUsage`.

See <a href="/docs/core/usage-tracking">Usage Tracking</a> for token reporting details.

A typical billing flow uses both:

```ts title="billing-flow.ts"
const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
  onUsage: (usage) => {
    billing.record(usage);
  },
});

await llm.call({
  userContent: 'Write a summary',
  reserveUsage: async ({ signal }) => {
    await billing.reserve({ signal });
  },
  refundUsage: async ({ signal }) => {
    await billing.refund({ signal });
  },
});
```
