title: Usage Tracking
description: Hook into successful LLM calls with provider-reported token usage
---

## Overview

VernLLM exposes `onUsage` for tracking token usage returned by the provider after a successful
completion.

This is useful for:

- billing calculations
- analytics
- cost monitoring
- request tracing
- usage dashboards

```ts title="usage-tracking-setup.ts"
const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
  onUsage: (usage) => {
    billing.record(usage);
  },
});
```

`onUsage` receives the following shape:

```ts title="token-usage-interface.ts"
interface TokenUsage {
  promptTokens: number;
  completionTokens: number;
  totalTokens: number;
  requestId: string;
  model: string;
}
```

## Usage fields

- **`promptTokens`** is the number of tokens sent to the model.
- **`completionTokens`** is the number of tokens generated by the model.
- **`totalTokens`** is the combined prompt and completion token count.
- **`requestId`** is the ID associated with the request. If you provide `requestId` in
  `call({ requestId })`, that value is preserved. Otherwise VernLLM generates a UUID automatically.
  This is useful for correlating usage records with logs or application events.
- **`model`** is the model that actually handled the request. This includes per-call model overrides,
  not only the default model configured on the VernLLM instance.

## When onUsage fires

`onUsage` fires once after a successful provider response.

The lifecycle is:

1. The request is sent.
2. The provider returns a completion.
3. VernLLM records the usage information.
4. JSON parsing and schema validation run.
5. The final result is returned.

<Callout type="info">
  `onUsage` fires after the provider completion succeeds but before JSON parsing and schema
  validation. This means a request can still fail later due to invalid JSON or schema validation
  after usage has already been reported.
</Callout>

## Failed calls

`onUsage` does not fire when a request ultimately fails.

This includes:

- exhausted retries
- provider errors
- timeout failures
- validation failures
- aborted requests

If retries are enabled, usage is only reported after the final successful completion, not once per
retry attempt.

<Callout type="warn">
  Some failed attempts may have consumed provider resources internally, but VernLLM cannot report
  usage unless the provider returns a successful response containing usage data.
</Callout>

## Callback failures

A failing `onUsage` callback cannot break an otherwise successful LLM request.

```ts title="safe-usage-callback.ts"
const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',

  onUsage: (usage) => {
    throw new Error('Billing system unavailable');
  },
});
```

If the callback throws:

- the error is logged
- the error is swallowed
- the original LLM response is still returned

<Callout>
  Usage tracking is treated as an observability hook, not part of the request execution path.
</Callout>

## Usage tracking with caching

Cache hits do not trigger `onUsage`.

When using `cachedCall` or `cachedLLMCall`:

- cache hits return the stored result without making an LLM request
- `onUsage` does not run for cached responses
- `onUsage` only runs when an actual provider request is completed

```ts title="cached-usage-tracking.ts"
const result = await llm.cachedLLMCall({
  cacheKey: `cv:${cvId}`,
  ttl: 3600,

  call: {
    systemPrompt,
    userContent,
  },
});
```

Only the request that populates the cache produces provider usage data.

<Callout type="info">
  If you need to enforce quotas before requests are sent, use `reserveUsage` and `refundUsage`
  instead. Usage tracking reports completed provider usage, while reservations control access.
</Callout>

## Example: Cost estimation

```ts title="usage-cost-estimation.ts"
const PRICE_PER_1K_TOKENS = {
  prompt: 0.005,
  completion: 0.015,
};

const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',

  onUsage: ({ promptTokens, completionTokens, requestId, model }) => {
    const cost =
      (promptTokens / 1000) * PRICE_PER_1K_TOKENS.prompt +
      (completionTokens / 1000) * PRICE_PER_1K_TOKENS.completion;

    logger.info(`[${requestId}] ${model} cost: $${cost.toFixed(4)}`);
  },
});
```
