---
title: Usage Tracking
description: Hook into every call's usage data
---

```ts title="usage-tracking-setup.ts"
const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
  onUsage: (usage) => {
    billing.record(usage);
  },
});
```

`onUsage` fires after every successful call, with the following shape:

```ts title="token-usage-interface.ts"
interface TokenUsage {
  promptTokens: number;
  completionTokens: number;
  totalTokens: number;
  requestId: string;
  model: string;
}
```

- **`requestId`** is whatever you passed to `call({ requestId: '...' })`, or an auto-generated UUID if you didn't. It is included in usage callbacks and internal logging, making it useful for correlating a usage record back to the originating request, joining usage data with application logs, tracing a request across services, or implementing your own billing reconciliation/deduplication logic.
- **`model`** reflects the model that actually served the request, including a per-call `model` override, not just the instance's default. Important if you bill different models at different rates.

## When it does and doesn't fire

<Callout>
  `onUsage` fires only after the call fully succeeds, meaning the raw completion, JSON parsing, and
  schema validation all passed. If the `onUsage` callback itself throws, that failure is logged and
  swallowed rather than propagated, it can't fail or retrigger retries on an otherwise-successful
  call. If you need to gate a call *before* it's dispatched (e.g. enforcing a quota), see
  [`reserveUsage`/`refundUsage`](/docs/core/usage-metering).
</Callout>

<Callout type="warn">
  `onUsage` only fires when the provider's response actually includes usage data. Not every adapter
  surfaces this identically, check your provider's response shape if usage isn't showing up.
</Callout>

- **On success**, once per completed call, after retries have finished (not once per retry attempt).
- **On failure**, `onUsage` never fires. If a failed attempt's response included usage data, that
  spend is reported through [`onUsageFailure`](#reporting-usage-on-failure) instead, not lost.
- **With caching**, a cache hit in `cachedCall` does not run the underlying LLM call, so `onUsage` does not fire for cached results. It only fires when a provider response is actually received.

## Reporting usage on failure

```ts title="usage-failure-setup.ts"
const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
  onUsage: (usage) => billing.record(usage),
  onUsageFailure: (usage, error) => {
    billing.record(usage);
    const tokens = usage.totalTokens || usage.promptTokens + usage.completionTokens;
    logger.warn(`call failed after spending ${tokens} tokens: ${error.type}`);
  },
});
```

`onUsageFailure` fires when a provider response arrives, and usage data was present on it, but VernLLM's own post-processing then fails, parsing, schema validation, or any other error raised after the response landed. It exists because `onUsage` only fires on full success: without it, tokens spent on an attempt that then failed would go unreported, even though the provider already charged for them.

<Callout>
  `onUsageFailure` fires once per failed attempt with extractable usage, not once per logical
  `call()`. A call that fails once and then succeeds on retry fires `onUsageFailure` for the failed
  attempt and `onUsage` for the successful one, both carrying their own real usage. It never fires
  for transport failures (timeout, network error, non-retryable status) or when the call was
  aborted, since in both cases there's no honest number, or no matching error type, to report. If
  the `onUsageFailure` callback itself throws, that failure is logged and swallowed, same as
  `onUsage`.
</Callout>

## Example: per-request cost estimation

```ts title="usage-cost-estimation.ts"
const PRICE_PER_1K_TOKENS = { prompt: 0.005, completion: 0.015 };

const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
  onUsage: ({ promptTokens, completionTokens, requestId, model }) => {
    const cost =
      (promptTokens / 1000) * PRICE_PER_1K_TOKENS.prompt +
      (completionTokens / 1000) * PRICE_PER_1K_TOKENS.completion;

    logger.info(`[${requestId}] ${model} cost: $${cost.toFixed(4)}`);
  },
});
```
