## With Zod

### Remember to install zod first!

<Tabs items={['pnpm', 'npm', 'yarn']}>
  <Tab value="pnpm">``` pnpm add zod ```</Tab>
  <Tab value="npm">``` npm install zod ```</Tab>
  <Tab value="yarn">``` yarn add zod ```</Tab>
</Tabs>

Pass a `schema` and get a typed, validated result. Works with any validator exposing `safeParse` (Zod v3/v4).

```ts title="candidate-schema-zod.ts"
import { z } from 'zod';

const CandidateSchema = z.object({
  name: z.string(),
  skills: z.array(z.string()),
});

const result = await llm.call({
  systemPrompt: 'Extract the candidate name and skills as JSON.',
  userContent: resumeText,
  schema: CandidateSchema,
});
```

<Callout type="warn">
  On a schema mismatch, `call` throws `LLMError('validation')` with `.issues` set to the validator's
  error object, without burning a retry.
</Callout>

<Callout type="info">
  `schema` only runs if the call actually parses JSON, which happens when `jsonMode` is `true` (the
  default) or `jsonSchema` is set. If you pass `jsonMode: false` alongside `schema` without also
  setting `jsonSchema`, `call` throws `LLMError('validation')` immediately.
</Callout>

## Provider-native JSON Schema mode

`schema` validates client-side after generation. `jsonSchema` sends the schema to the provider using its native structured-output mechanism.

```ts title="candidate-json-schema-mode.ts"
const result = await llm.call({
  systemPrompt: 'Extract the candidate name and skills.',
  userContent: resumeText,
  jsonSchema: {
    name: 'Candidate',
    schema: {
      type: 'object',
      properties: {
        name: { type: 'string' },
        skills: { type: 'array', items: { type: 'string' } },
      },
      required: ['name', 'skills'],
    },
    strict: true,
    description: 'A candidate profile',
  },
  schema: CandidateSchema,
});
```

- **`jsonSchema` implies JSON mode.** It overrides `jsonMode: false` and sends the request as structured JSON.
  **`strict` is forwarded when supported by the adapter.** Enforcement depends on the adapter: OpenAI/Groq use JSON Schema mode, Anthropic uses tool strictness, Bedrock forwards tool strictness where supported, and Gemini uses schema-based structured output without relying on `strict`.
- **`description` is forwarded where supported.** OpenAI-shaped providers receive it in the schema object. Anthropic and Bedrock include it in generated tool definitions. Gemini includes it in `responseSchema`.

<Callout>
  Anthropic uses native tool use for structured output. The schema is passed as the tool
  `input_schema` and `tool_choice` forces the model to call it. A client-side `schema` is still
  recommended when you need validation guarantees across providers.
</Callout>
