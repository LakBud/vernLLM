Every call goes through one synchronous function. It collects the rules that apply, combines them
with set operations, and either narrows the targets, leaves them alone, or denies the call. Nothing
before `next()` waits, so the decision is made before anything else can happen.

## The pipeline

| Step       | What it does                                                                       |
| ---------- | ---------------------------------------------------------------------------------- |
| Facts      | Target facts and call facts are built, and costly ones only when a rule reads them |
| Applicable | Enforced rules whose `when` holds and that no active exception covers              |
| Combine    | Allows add up, forbids subtract, and a forbid always wins                          |
| Flags      | Flags from the applicable rules are merged, and `false` wins                       |
| Decide     | Denied when nothing is left, narrowed when some were removed, otherwise untouched  |
| Report     | One `policy.decision` event, emitted before the call goes on                       |
