---
title: Hosted detectors
description: Detectors backed by a provider's classifier or a model of your own, so a check can catch harmful content and rules that no pattern describes
---

`patterns` and `keywords` match text. A hosted detector asks a provider's classifier instead. It is
still a plain [detector](/docs/extensions/guard/features/checks#detectors): the guard keeps deciding
labels, redaction, the memo, timeouts and what a failure means, and the provider only answers what
is in the text.

## openaiModeration

Harmful content, from OpenAI's Moderation API, which is free: hate, harassment, self-harm, sexual,
violence and illicit.

```ts title="guard-moderation.ts"
import OpenAI from 'openai';
import { guardMiddleware, openaiModeration } from 'vern-llm-guard';

const moderation = openaiModeration({
  client: new OpenAI(),
  model: 'omni-moderation-2024-09-26',
  thresholds: { 'self-harm': 0.3 },
});

guardMiddleware({
  version: '2026-10-27.1',
  checks: [
    {
      id: 'self-harm',
      detect: moderation.only('self-harm', 'self-harm/intent', 'self-harm/instructions'),
      action: 'block',
      on: ['user', 'output'],
    },
    {
      id: 'harm',
      detect: moderation.only('violence', 'hate', 'harassment'),
      on: ['user', 'output'],
    },
  ],
});
```

<Callout type="warn">
  The text a check reads is sent to OpenAI. Use it only where the app already trusts OpenAI with
  that text.
</Callout>

### Findings

- One finding per category that counts, labeled `moderation.<category>`, such as
  `moderation.self-harm/intent`
- The API returns no positions, so a finding covers the whole text. These checks label and block,
  and a `redact` check on them blocks
- `only(...)` takes the category names and gives a detector over the same requests and cache.
  Several checks over one text cost one request
- A long text is checked in chunks, and a category counts if it counts in any of them

### Errors and cost

- Any error or malformed answer is thrown. The check's `onError` decides, and `closed` is the default
- The check's `timeoutMs` cancels the request, and a request that nobody waits for any more is
  cancelled with it
- The memo and the detector's cache send each text once, so a long history is not checked again
  every turn

## llmClassifier

Rules only you can describe, judged by a model: "recommends a specific investment", "names a
competitor", "has nothing to do with support". You write the categories in plain language.

```ts title="guard-classifier.ts"
import Anthropic from '@anthropic-ai/sdk';
import { VernLLM } from 'vern-llm';
import { fromAnthropic } from 'vern-llm/adapters';
import { guardMiddleware, llmClassifier } from 'vern-llm-guard';

const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

const classifier = llmClassifier({
  llm: new VernLLM({ client: fromAnthropic(anthropic), model: 'a-small-model' }),
  categories: {
    investment_advice: 'Recommends buying or selling specific securities or funds',
    competitor: 'Names or compares against a competitor',
    off_topic: 'Has nothing to do with support for our product',
  },
  quotes: true,
});

guardMiddleware({
  version: '2026-10-29.1',
  checks: [
    { id: 'advice', detect: classifier.only('investment_advice'), on: 'output', action: 'block' },
    { id: 'competitor', detect: classifier.only('competitor'), on: 'output', action: 'redact' },
    { id: 'topic', detect: classifier.only('off_topic'), on: 'user', mode: 'audit' },
  ],
});
```

<Callout type="warn">
  Give it a `VernLLM` of its own. A guard on that instance refuses the classifier's calls on the
  first one, because it would scan each classification and call the classifier again. The model sees
  the text it judges, so use one the app already trusts with that text.
</Callout>

### Findings

- One finding per category the model names, labeled `classifier.<category>`
- With `quotes`, each quote is located in the text and becomes a span, so a `redact` check can
  mask it. A quote that cannot be found gives a finding over the whole text, and a `redact` check
  blocks rather than miss it
- Without `quotes`, findings cover the whole text. These checks label and block
- `only(...)` takes your category names and gives a detector over the same calls and cache

### Its own VernLLM

- Every call the classifier makes carries a marker in the call's `state`. A guard refuses a marked
  call with an `invalid_params` error that says "Give llmClassifier its own VernLLM", and warns
  once
- The check then fails like any other error, so `onError` decides. The mistake shows on the first
  call instead of as a loop of classifications

### How it asks

- Every text goes in a tag with a random name, new for each call, and the prompt says that
  everything inside is data to classify, never instructions
- The answer is constrained by a strict schema whose categories are an enum, and checked again
  here. An id that is missing, repeated or unknown, or a category that was not given, is an error
- `temperature` is `0`, so answers stay stable under the memo. Changing the categories, the
  instructions or the model changes what is found, so give the guard a new `version`
- Any error or malformed answer is thrown, and the check's `onError` decides. The check's
  `timeoutMs` cancels the call
- Verdicts are matched to texts by id, and an answer that does not cover each text exactly once is
  an error. By default (`onError: 'closed'`) that blocks the call. With `onError: 'open'` the call
  goes on without this check's findings

## Measure before you enforce

A classifier is a heuristic too. Run a new check in `mode: 'audit'`, then measure it with
[`evaluate`](/docs/extensions/guard/features/rollout) over a labeled set before it blocks a call.
