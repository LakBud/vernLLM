---
title: Hosted detectors
description: Detectors backed by a provider's classifier, a model of your own or a Bedrock guardrail, to catch harmful content and rules no pattern describes
---

`patterns` and `keywords` match text. A hosted detector asks a provider's classifier instead. It is
still a plain [detector](/docs/extensions/guard/features/checks#detectors): the guard keeps deciding
labels, redaction, the memo, timeouts and what a failure means, and the provider only answers what
is in the text.

## openaiModeration

Harmful content, from OpenAI's Moderation API, which is free: hate, harassment, self-harm, sexual,
violence and illicit.

```ts title="guard-moderation.ts"
import OpenAI from 'openai';
import { guardMiddleware, openaiModeration } from 'vern-llm-guard';

const moderation = openaiModeration({
  client: new OpenAI(),
  model: 'omni-moderation-2024-09-26',
  thresholds: { 'self-harm': 0.3 },
});

guardMiddleware({
  version: '2026-10-27.1',
  checks: [
    {
      id: 'self-harm',
      detect: moderation.only('self-harm', 'self-harm/intent', 'self-harm/instructions'),
      action: 'block',
      on: ['user', 'output'],
    },
    {
      id: 'harm',
      detect: moderation.only('violence', 'hate', 'harassment'),
      on: ['user', 'output'],
    },
  ],
});
```

<Callout type="warn">
  The text a check reads is sent to OpenAI. Use it only where the app already trusts OpenAI with
  that text.
</Callout>

### Findings

- One finding per category that counts, labeled `moderation.<category>`, such as
  `moderation.self-harm/intent`
- The API returns no positions, so a finding covers the whole text. These checks label and block,
  and a `redact` check on them blocks
- `only(...)` takes the category names and gives a detector over the same requests and cache.
  Several checks over one text cost one request
- A long text is checked in chunks, and a category counts if it counts in any of them

### Images

Images are off by default. Set `images: true` and a check on user messages also sends the images in
the request. Text goes the way it always did, and each image is its own request.

- PNG, JPEG, WebP and GIF, up to 20 MB each. With `images`, `unsupportedImages: 'error'` (default) throws for any
  other image, so `onError` decides. `'skip'` leaves it unread and counts it as unscanned
- Findings on an image have no offsets, so a `redact` check on them blocks
- Images are sent to OpenAI only with `images: true`

### Errors and cost

- Any error or malformed answer is thrown. The check's `onError` decides, and `closed` is the default
- The check's `timeoutMs` cancels the request, and a request that nobody waits for any more is
  cancelled with it
- The memo and the detector's cache send each text once, so a long history is not checked again
  every turn

## llmClassifier

Rules only you can describe, judged by a model: "recommends a specific investment", "names a
competitor", "has nothing to do with support". You write the categories in plain language.

```ts title="guard-classifier.ts"
import Anthropic from '@anthropic-ai/sdk';
import { VernLLM } from 'vern-llm';
import { fromAnthropic } from 'vern-llm/adapters';
import { guardMiddleware, llmClassifier } from 'vern-llm-guard';

const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

const classifier = llmClassifier({
  llm: new VernLLM({ client: fromAnthropic(anthropic), model: 'a-small-model' }),
  categories: {
    investment_advice: 'Recommends buying or selling specific securities or funds',
    competitor: 'Names or compares against a competitor',
    off_topic: 'Has nothing to do with support for our product',
  },
  quotes: true,
});

guardMiddleware({
  version: '2026-10-29.1',
  checks: [
    { id: 'advice', detect: classifier.only('investment_advice'), on: 'output', action: 'block' },
    { id: 'competitor', detect: classifier.only('competitor'), on: 'output', action: 'redact' },
    { id: 'topic', detect: classifier.only('off_topic'), on: 'user', mode: 'audit' },
  ],
});
```

<Callout type="warn">
  Give it a `VernLLM` of its own. A guard on that instance refuses the classifier's calls on the
  first one, because it would scan each classification and call the classifier again. The model sees
  the text it judges, so use one the app already trusts with that text.
</Callout>

### Findings

- One finding per category the model names, labeled `classifier.<category>`
- With `quotes`, each quote is located in the text and becomes a span, so a `redact` check can
  mask it. A quote that cannot be found gives a finding over the whole text, and a `redact` check
  blocks rather than miss it
- Without `quotes`, findings cover the whole text. These checks label and block
- `only(...)` takes your category names and gives a detector over the same calls and cache

### Risk levels

With `levels: true` the model gives each category a level from 0 to 3 instead of a yes or no.
Findings are labeled `classifier.<category>:<level>` for level 1 and up. `only` takes a minimum, so
a check can block only the serious ones.

```ts title="guard-levels.ts"
const classifier = llmClassifier({ llm, categories, levels: true });
classifier.only('competitor', { minLevel: 2 }); // levels 2 and 3
```

- `minLevel` is 1 to 3 and needs `levels: true`
- Turning `levels` on changes what is found, so give the guard a new `version`

### Its own VernLLM

- Every call the classifier makes carries a marker in the call's `state`. A guard refuses a marked
  call with an `invalid_params` error that says "Give llmClassifier its own VernLLM", and warns
  once
- The check then fails like any other error, so `onError` decides. The mistake shows on the first
  call instead of as a loop of classifications

### How it asks

- Every text goes in a tag with a random name, new for each call, and the prompt says that
  everything inside is data to classify, never instructions
- The answer is constrained by a strict schema whose categories are an enum, and checked again
  here. An id that is missing, repeated or unknown, or a category that was not given, is an error
- `temperature` is `0`, so answers stay stable under the memo. Changing the categories, the
  instructions or the model changes what is found, so give the guard a new `version`
- Any error or malformed answer is thrown, and the check's `onError` decides. The check's
  `timeoutMs` cancels the call
- Verdicts are matched to texts by id, and an answer that does not cover each text exactly once is
  an error. By default (`onError: 'closed'`) that blocks the call. With `onError: 'open'` the call
  goes on without this check's findings

## bedrockGuardrail

The guardrails your team already manages in Amazon Bedrock: denied topics, content filters, sensitive
information, regexes and word lists. It lives in `vern-llm-bedrock`, so the guard itself takes no
AWS dependency. Its options are on the [Guardrails page](/docs/integrations/bedrock/guardrails).

```ts title="guard-bedrock.ts"
import { BedrockRuntimeClient } from '@aws-sdk/client-bedrock-runtime';
import { bedrockGuardrail } from 'vern-llm-bedrock/guardrail';
import { guardMiddleware } from 'vern-llm-guard';

const aws = bedrockGuardrail({
  client: new BedrockRuntimeClient({ region: 'eu-west-1' }),
  guardrailIdentifier: 'gr-abc123',
  guardrailVersion: '3',
});

guardMiddleware({
  version: '2026-10-29.1',
  checks: [
    { id: 'pii', detect: aws.only('pii', 'regex'), action: 'redact', on: ['user', 'output'] },
    { id: 'topics', detect: aws.only('topic'), action: 'block', on: ['user', 'tool'] },
    { id: 'harmful', detect: aws.only('content'), action: 'block', parallel: true },
  ],
});
```

<Callout type="warn">
  The text a check reads is sent to Bedrock. Use a published guardrail version: `DRAFT` can change
  at any time, so it warns once and turns the detector's cache off.
</Callout>

### Images and grounding

- `images: true` also checks the images in a request, as `content.<type>` findings with no span.
  PNG and JPEG only, up to 4 MB and 8000 by 8000 pixels. Images are sent to Bedrock only with the
  option set
- `aws.grounding()` judges an output against the tool results of the call, as
  `grounding.GROUNDING` or `grounding.RELEVANCE` over the chunk that failed. Use it as an `output`
  check, with `release: 'immediate'` on streams
- Limits and options are on the [Guardrails page](/docs/integrations/bedrock/guardrails)

### Findings

- Labeled `pii.<type>`, `regex.<name>`, `word.<type>`, `topic.<name>` or `content.<type>`
- Matches in sensitive information, regexes and words are located in the text and become spans,
  so a `redact` check can mask them. A match that cannot be found gives a finding over the whole
  text, and a `redact` check blocks rather than miss it
- Topics and content filters return no match, so they cover the whole text. These checks label and
  block
- The check's `action` decides what happens. Bedrock's own action is ignored
- `only(...)` takes `pii`, `regex`, `word`, `topic` and `content`, and gives a detector over the same
  requests and cache. Three checks on one guardrail share its in flight requests and cached
  results, so a text is not sent again while its result is cached

## Choosing between them

|            | `openaiModeration` | `llmClassifier`                   | `bedrockGuardrail`                    |
| ---------- | ------------------ | --------------------------------- | ------------------------------------- |
| Cost       | Free               | One small model call per new text | Per text unit and policy, per request |
| Categories | OpenAI's thirteen  | Yours, in plain language          | Yours, configured in AWS              |
| Spans      | No                 | With `quotes`                     | For PII, regexes and words            |
| Setup      | An OpenAI key      | A second `VernLLM`                | A guardrail and IAM                   |
| Best for   | Harm, cheaply      | Business rules no service has     | Teams already governed in AWS         |

They combine: `openaiModeration` for harm on every call, `llmClassifier` for one business rule on
the answer, `patterns` for secrets.

## Cost

- The memo and each detector's cache send a text once, so a long history is not checked again every
  turn. A text is remembered per source: an earlier answer that comes back in the history is read
  as input, where it was first read as output, so a provider can see it once more
- Point checks at the sources that need them. `on: ['user', 'tool']` leaves out the system prompt
  that every call repeats
- Bedrock bills per text unit, rounded up for each request, and a request carries one text
- The classifier costs one model call per new text. Use a small model, raise `batchSize` for volume,
  and use `parallel: true` on a block check to hide the latency
- Every detector takes `onUsage`, which reports what each request cost

## When a hosted detector fails

A network error, a throttled request, a malformed answer or a result for the wrong number of texts
is thrown as it is, and the check's `onError` decides. With `closed`, the default, a failed blocking
check blocks the call, which is right for a check you rely on, and a failed labeling check makes its
labels unknown without blocking. Use `open` for a check that is a convenience, so an outage at the
provider does not become an outage of your app. The check's `timeoutMs` cancels the request.

## Measure before you enforce

A hosted detector is a heuristic too. Run a new check in `mode: 'audit'`, then measure it with
[`evaluate`](/docs/extensions/guard/features/rollout) over a labeled set before it blocks a call.
