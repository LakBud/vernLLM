`vern-llm-router` is one middleware that decides which of a call's targets are tried first. You
write routes that match a call by its `context`, tools, JSON output, or size, and each route orders
its targets with a strategy: in declared order, weighted, least busy, or ranked by measured latency,
cost, and quality. A target with an open breaker or an exhausted rate limit moves to the back.

<Callout type="info">
  The router only reorders targets the call already has. It never adds one, never changes what a
  call returns or throws, and if deciding fails the call runs exactly as it would without it.
</Callout>

## Basic usage

```ts title="router-basic-usage.ts"
import { VernLLM } from 'vern-llm';
import { routerMiddleware } from 'vern-llm-router';

const router = routerMiddleware({
  health: () => llm, // lazy, since llm is created after this middleware
  routes: [
    { name: 'bulk', when: { context: { tier: ['free', 'trial'] } }, targets: ['small'] },
    { name: 'tools', when: { hasTools: true }, exclude: ['small'] },
    { name: 'default', targets: [['main'], '*'] },
  ],
  capabilities: { small: { contextWindow: 32_000, tools: false } },
});

const llm = new VernLLM({
  client,
  model: 'main',
  fallback: [{ client: smallClient, model: 'mini', name: 'small' }],
  middleware: [router],
});
```

The first route whose `when` matches decides the order. Register the middleware once per
`VernLLM`: two entries in one `middleware` array throw at construction.

## Try a rule before you ship it

`router.preview()` returns the decision a call would get right now, without calling anything:

```ts title="router-preview.ts"
const decision = router.preview({
  request: { model: 'main', messages: [{ role: 'user', content: 'hi' }] },
  context: { tier: 'free' },
});
// { route: 'bulk', strategy: 'ordered', order: ['small'], excluded: [...], demoted: [], explored: false }
```

For a rollout, set `apply: false` first. Every decision is computed and emitted and no call
changes, so you can compare against the declared order before switching it on, see
[Observability](/docs/extensions/router/features/observability).

## With policy

The router decides what is preferred, and [`vern-llm-policy`](/docs/extensions/policy) decides what
is allowed. Policy runs first and removes targets, so the router only ever orders what is left.
Prefer an open route list such as `targets: [['main'], '*']`, which keeps working when policy
removes a target, and see [Router and usage](/docs/extensions/policy/features/router) for the
details.
