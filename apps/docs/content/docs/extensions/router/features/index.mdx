Every call goes through one synchronous function that filters targets, groups them in tiers, orders
each tier with a strategy, and finally moves unhealthy targets back. The same function backs
`router.preview()`, so a preview and a real call agree.

## The pipeline

| Step     | What it does                                                                      |
| -------- | --------------------------------------------------------------------------------- |
| Match    | The first route whose `when` holds, or the one forced with `routerRouteKey`       |
| Filter   | `targets` and `exclude`, then `capabilities` that the request does not fit        |
| Tiers    | Targets are grouped, and each tier is tried before the next                       |
| Strategy | Orders the targets inside each tier                                               |
| Demote   | Moves back targets that are over a limit, cannot meet the deadline, or are unwell |
