The shapes below are what the middleware hands back. Money fields are USD as plain numbers, rounded
from integer nano dollars only when they are reported.

`model` to narrow to one target name or model.

## Events

Custom events with `v: 1`, kept by the logger's default `usage.*` allowlist.

<TypeTable
  type={{
    'usage.budget_warning': {
      description:
        'Once per threshold, budget and window, when spend plus holds reach a warnAt value.',
      type: '{ v: 1; scope: string; unit: "usd" | "tokens"; limit: number; threshold: number; mode: "hard" | "soft"; used: number }',
    },
    'usage.budget_exceeded': {
      description:
        'A hard budget rejected a call, just before the error is thrown, or a soft budget reached its limit.',
      type: '{ v: 1; scope: string; unit: "usd" | "tokens"; limit: number; remaining: number; mode: "hard" | "soft"; blocked: boolean }',
    },
  }}
/>

`scope` is the label of the budget, such as `tenantId=acme per day`. `used` is a share from 0 to 1, and `threshold` is the `warnAt` value that was crossed. `blocked` is `true` when the call was rejected and `false` for a soft budget, whose call completes.

## Rejection

A call over budget, or a failing store with `onStoreError: 'deny'`, throws an `LLMError` before any
provider is contacted:

| Field     | Value                                                           |
| --------- | --------------------------------------------------------------- |
| `type`    | `'quota_exceeded'`                                              |
| `code`    | `'budget_exceeded'`                                             |
| `message` | `Budget exceeded: <label>`, or `Usage budget store unavailable` |
| `cause`   | The store's error, only for a failing store                     |

It is not retryable, never counts toward the circuit breaker, and the default `fallbackOn` stops on
it.
