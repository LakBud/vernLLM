Every call that can be hedged goes through one flow: skip when it should not be hedged, otherwise
start the call, wait for the delay, and if the call is still open and a budget token is free, start
the same call on another target and keep the first success.

## How the extensions fit

The hedge sits at position `10`, inside the logger, guard, policy, usage and router, and outside the
attempts it races. Each of them sees one call.

| With    | What happens                                                                                            |
| ------- | ------------------------------------------------------------------------------------------------------- |
| Router  | The hedge goes to the router's second choice. Its attempt counts as load like any other                 |
| Policy  | A removed target never reaches `ctx.targets`, so it cannot be hedged to                                 |
| Guard   | Input is checked once. Each attempt is redacted for its own target, and the kept answer is checked once |
| Usage   | One reservation. Both chains' spend is counted, and the unkept part is reported as `unkeptUsd`          |
| Logger  | One record per call with the kept chain's latency. `hedge.*` events are kept by default                 |
| Caching | In `cachedCall` a winning hedge's answer is cached, and a cache hit is never hedged                     |
