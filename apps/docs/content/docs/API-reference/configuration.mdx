title: Configuration

Everything below is set once on the `VernLLM` instance and applies to every `call()` unless overridden per request. Nothing is required beyond `client` and `model`; every other option has a sensible default.

```ts title="vernllm-instance-config.ts"
const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
  maxRetries: 1,
  timeoutMs: 25_000,
  baseDelayMs: 500,
  defaultMaxTokens: 1000,
  nonRetryableStatus: [400, 401, 403, 404, 422],
  circuitBreaker: true,
  debug: false,
  cache: new InMemoryCacheAdapter(), // optional, defaults to this anyway
  parseJson: (content) => {
    try {
      return JSON.parse(content);
    } catch {
      return undefined;
    }
  },
  onUsage: (usage) => billing.record(usage), // optional, no default
  logger: myLogger, // optional, defaults to console-based logger gated by `debug`
});
```

## Required

## Retry & timeout

| Option               | Default                     | Notes                                                                                                                                       |
| -------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `maxRetries`         | `1`                         | Retries after the first attempt, so 2 attempts total by default. `maxRetries: 3` means up to 4 attempts.                                    |
| `timeoutMs`          | `25000`                     | Per-attempt timeout, not a total call timeout. Each retry receives its own timeout window.                                                  |
| `baseDelayMs`        | `500`                       | Base delay for exponential backoff with jitter. Provider `Retry-After` values are honored when present and capped to the retry delay limit. |
| `nonRetryableStatus` | `[400, 401, 403, 404, 422]` | HTTP status codes that skip retries because they are treated as permanent failures.                                                         |

## Request defaults

| Option             | Default            | Notes                                                                                                                                                                     |
| ------------------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `defaultMaxTokens` | `1000`             | Used when a call does not provide `maxTokens`.                                                                                                                            |
| `parseJson`        | `defaultParseJson` | Custom parser for responses. It may return `undefined` when parsing fails, which causes `LLMError('parse')`. Thrown parser errors are also converted into parse failures. |

## Caching

| Option  | Default                      | Notes                                                                                                                                                                                                                                                                                |
| ------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `cache` | `new InMemoryCacheAdapter()` | Used only by `cachedCall` and `cachedLLMCall`, not normal `call()`. The default cache is local to the current process and is not shared across instances. Use a shared adapter such as Redis or Upstash for multi-process deployments. See <a href="/docs/core/caching">Caching</a>. |

## Observability

| Option    | Default                       | Notes                                                                                                                                                                                                       |
| --------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `onUsage` | none                          | Called after a successful provider response when usage data exists. It fires once per completed request, not once per retry attempt. Cached responses do not trigger it because no provider request occurs. |
| `logger`  | console based `ConsoleLogger` | Implement the `Logger` interface to route logs elsewhere, such as pino or winston. See <a href="/docs/core/logging">Pluggable Logger</a>.                                                                   |
| `debug`   | `false`                       | Controls `logger.debug` output only. Warning and error logs are still emitted regardless of this flag.                                                                                                      |

## Circuit breaker

| Option           | Default  | Notes                                                                                                                                                                                       |
| ---------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `circuitBreaker` | disabled | Pass `true` for default settings (`threshold: 5`, `cooldownMs: 30_000`), or provide `{ threshold, cooldownMs }` to tune them. See <a href="/docs/core/circuit-breaker">Circuit Breaker</a>. |

## Per call defaults and overrides

The following options are configured per `call()` and have defaults worth knowing:

| Option         | Default | Notes                                                                                                                                               |
| -------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `temperature`  | `0.2`   | VernLLM always sends a temperature value unless overridden.                                                                                         |
| `jsonMode`     | `true`  | Responses are parsed as JSON by default. Set `jsonMode: false` to return raw text. If `jsonSchema` is provided, JSON mode is enabled automatically. |
| `systemPrompt` | none    | Omitting it skips the system message entirely rather than sending an empty one.                                                                     |

The rest, including `userContent`, `model`, `maxTokens`, `reasoningEffort`, `schema`, `jsonSchema`,
`signal`, and `requestId`, have no additional defaults beyond falling back to instance configuration
where applicable or remaining undefined when omitted.

`userContent` remains required and accepts either a plain `string` for text-only requests or a
`ContentBlock[]` for multimodal input (text and images).

## Multimodal `userContent`

`ContentBlock` is the shape used when `userContent` is passed as an array instead of a plain string:

```ts title="content-block-types.ts"
interface TextBlock {
  type: 'text';
  text: string;
}

interface ImageBlock {
  type: 'image';
  data: string; // base64-encoded bytes, no `data:` prefix
  mimeType: string; // e.g. 'image/png', 'image/jpeg', 'image/webp', 'image/gif'
}

type ContentBlock = TextBlock | ImageBlock;
```

<Callout type="info">
  Image blocks are validated before sending. Supported MIME types are `image/png`, `image/jpeg`,
  `image/gif`, and `image/webp`.
</Callout>
