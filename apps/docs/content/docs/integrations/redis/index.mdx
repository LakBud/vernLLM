`vern-llm-redis` is the production version of the illustrative Redis adapters shown throughout
[Customization](/docs/customization): a `CircuitBreakerAdapter`, `RateLimiterAdapter`, and
`CacheAdapter`, each backed by Redis instead of process memory. Reach for it once VernLLM runs on
more than one instance and those instances need a shared view of failures, limits, or cached
responses.

`vern-llm` is a peer dependency, so `vern-llm-redis` shares the copy your app already uses. That
keeps the `LLMError` these adapters throw the same class your own `instanceof` checks see. Current
npm, pnpm and yarn install a missing peer for you.

Redis 5 or newer is required. The adapters are tested against Redis 5.0, 6.2, 7.0, 7.2, 7.4 and
8.0, and against 7.0 and 8.0 Redis Clusters.

## Basic usage

Every adapter takes a Redis client as its first argument, wrapped through `fromIoredis` or
`fromNodeRedis` so both clients present the same shape internally, and an options object as its
second:

<Tabs items={['ioredis', 'node-redis']}>
  <Tab value="ioredis">

```ts title="redis-basic-usage-ioredis.ts"
import Redis from 'ioredis';
import OpenAI from 'openai';
import { VernLLM } from 'vern-llm';
import { redisCircuitBreaker, redisRateLimit, redisCache, fromIoredis } from 'vern-llm-redis';

const client = fromIoredis(new Redis());
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
  circuitBreaker: redisCircuitBreaker(client),
  rateLimit: redisRateLimit(client, { requestsPerMinute: 500 }),
  cache: redisCache(client),
});
```

  </Tab>
  <Tab value="node-redis">

```ts title="redis-basic-usage-node-redis.ts"
import { createClient } from 'redis';
import OpenAI from 'openai';
import { VernLLM } from 'vern-llm';
import { redisCircuitBreaker, redisRateLimit, redisCache, fromNodeRedis } from 'vern-llm-redis';

const raw = createClient();
await raw.connect();
const client = fromNodeRedis(raw);
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

const llm = new VernLLM({
  client: openai,
  model: 'gpt-4o',
  circuitBreaker: redisCircuitBreaker(client),
  rateLimit: redisRateLimit(client, { requestsPerMinute: 500 }),
  cache: redisCache(client),
});
```

  </Tab>
</Tabs>

<Callout type="warn">
  `fromIoredis` is close to a no-op, ioredis already matches the shape this package needs, it exists
  for type safety and symmetry with `fromNodeRedis`. `fromNodeRedis` does real work: node-redis's
  option-object call shapes (`set`'s `{ PX }`, `eval`'s `{ keys, arguments }`) get translated onto
  the positional, ioredis-shaped interface every adapter is written against. Neither client works if
  passed to an adapter unwrapped.
</Callout>

Every VernLLM instance sharing the same `keyPrefix` and Redis database coordinates together. Give
unrelated services their own prefix, otherwise their circuit breaker, rate limit, or cache state
collides with each other's.
