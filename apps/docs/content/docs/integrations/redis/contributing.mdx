This page covers `packages/vern-llm-redis` specifically. For the coding standard and PR checklist
that apply repo wide, see [Contributing](/docs/contributing).

## Setup

Fork the repo and branch off `main`, then install the workspace:

```bash
pnpm install
```

Integration tests need a local `redis-server` running, this is a real setup difference from
`vern-llm`'s suite, which needs no external service: its tests use fakes and mocks, or a local
loopback HTTP server standing in for a provider.

## Coding standard

Follow the same reliability and typing standard as `vern-llm`: handle unusual inputs on purpose,
explain non obvious decisions with a short comment, and keep `any` as a last resort. Redis specific
commands (`eval`, pub or sub) stay inside `packages/vern-llm-redis`, nothing in `vern-llm` itself
should know Redis exists.

## Scripts

These are `packages/vern-llm-redis`'s own scripts, exactly as they appear in its `package.json`.
Run them with `pnpm run <script>` from inside `packages/vern-llm-redis`, or `pnpm nx run
vern-llm-redis:<script>` from the repo root:

```json title="packages/vern-llm-redis/package.json"
"scripts": {
  "build": "tsdown",
  "dev": "tsdown --watch",
  "smoke-test": "node scripts/smoke-test.ts",
  "typecheck": "tsc -p tsconfig.json --noEmit",
  "typecheck:test": "tsc -p tsconfig.test.json",
  "lint": "oxlint .",
  "lint:fix": "oxlint . --fix",
  "test": "vitest run",
  "test:unit": "vitest run --project unit",
  "test:unit:coverage": "vitest run --project unit --coverage",
  "test:int": "vitest run --project integration",
  "test:int:coverage": "vitest run --project integration --coverage",
  "test:watch": "vitest",
  "test:coverage": "vitest run --coverage",
  "changeset": "changeset",
  "version-packages": "changeset version",
  "prepublishOnly": "pnpm run typecheck && pnpm run build && pnpm run size && pnpm run smoke-test",
  "size": "size-limit"
}
```

`test:int` and `test:int:coverage` need a local `redis-server` running, this is a real setup
difference from `vern-llm`'s suite, which needs no external service. Set `REDIS_PORT` to run
the same suite against another server, for example an older Redis build on a different port. The
cluster tests start their own cluster, see [Cluster tests](#cluster-tests). `prepublishOnly` runs
automatically before publish and isn't something you need to run by hand, it's listed here since it
shows the exact sequence a release goes through: typecheck, build, size, smoke test.

## Cluster tests

`test:int` starts a throwaway 3 node Redis Cluster for `cluster.int.test.ts`, so there is nothing
to set up by hand. It only needs `redis-server` on your `PATH`, the same binary as your local
Redis.

1. The nodes use random free ports, so your Redis on 6379 is never touched.
2. The cluster forms in the background. Only the cluster test file waits, about 2 seconds.
3. The nodes and their temp directories are removed when the run ends, including on Ctrl-C.

To use a cluster you already run, set `REDIS_CLUSTER_NODES` to a comma separated `host:port` list
and nothing is started:

```bash
REDIS_CLUSTER_NODES=127.0.0.1:7001,127.0.0.1:7002,127.0.0.1:7003 pnpm run test:int
```

If `redis-server` is missing, the cluster tests skip locally and print the reason. When `CI` is set
they fail the run instead, so they can never quietly stop running. CI installs `redis-server` for
this in its integration job.

## Before opening a PR

Every PR touching `packages/vern-llm-redis` runs through the same CI workflows described in
[Development](/docs/development#ci). Run the equivalent commands locally first:

| Check                          | Local command                                                                                                  |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Lint                           | `pnpm nx run vern-llm-redis:lint`                                                                              |
| Typecheck source               | `pnpm nx run vern-llm-redis:typecheck`                                                                         |
| Typecheck tests                | `pnpm nx run vern-llm-redis:typecheck:test`                                                                    |
| Unit tests + coverage          | `pnpm nx run vern-llm-redis:test:unit:coverage`                                                                |
| Integration tests              | `pnpm nx run vern-llm-redis:test:int:coverage`, needs a local `redis-server`                                   |
| Build, bundle size, smoke test | `pnpm nx run vern-llm-redis:build && pnpm nx run vern-llm-redis:size && pnpm nx run vern-llm-redis:smoke-test` |
| Changeset present              | `pnpm changeset status --since=origin/main`                                                                    |

## Changesets

Record your change with:

```bash
pnpm nx run vern-llm-redis:changeset
```

`vern-llm-redis` versions and releases independently of `vern-llm`, on its own changelog. See
[Development](/docs/development#ci) for what drives the release itself.
